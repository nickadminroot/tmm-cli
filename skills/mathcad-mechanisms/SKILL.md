# Исследование механизмов в классическом Mathcad

Используй этот навык, когда нужно получить редактируемый лист классического Mathcad для ТММ. Папка содержит семь ручных Python-переносов учебных фрагментов, общий адаптер, фотографии исходных страниц и минимально необходимый исходный код `xmcd`. HTML-просмотрщик, отчёты и служебные индексы в поставку не входят.

## Место в курсовой работе

Выбери нужные [разделы задания](https://github.com/nickadminroot/tmm-cli/blob/main/WORKFLOW.md):
их состав и порядок могут различаться. Курсовой проект может включать синтез,
сборку YAML, кинематику, динамику, аналитическую кинетостатику и исследования
зацепления/кулачка. Курсовое ДЗ использует сборку YAML, кинематику и листы
одного положения (кинематика и графическая кинетостатика); остальные разделы
проекта автоматически в ДЗ не переносить.

Синтез оформляй сразу в
XMCD вместе с [metric-synthesis](../metric-synthesis/SKILL.md): исходные данные,
редактируемые уравнения, решение, невязки и выбранные размеры. Служебные JSON
генераторов — диагностические приложения, а не результат для пользователя.

Кинематику и аналитическую кинетостатику можно начать с XMCD сайта или CLI:
прочитай существующий лист через `Worksheet.read(...)`, редактируй типизированные
регионы и сохраняй через `Worksheet.write(...)`. Доведи обозначения, пояснения,
таблицы, графики и разбиение до оформления задания; сохрани связь разделов.

Динамика сайта/CLI находится в альфе. Прочитай полученный динамический фрагмент
только для ознакомления; разработай проверенный расчёт самостоятельно и замени
фрагмент своим, при необходимости удалив исходный. Перед удалением проверь
зависимости следующих разделов от его обозначений. Пересчитай аналитическую
кинетостатику по окончательным скоростям, ускорениям, нагрузкам и инерциям.

Для каждого графика окончательного Mathcad подготовь свою сцену из тех же
данных и отрендери её в КОМПАС по
[tmm-graphics](../tmm-graphics/SKILL.md). Схемы, графики, диаграммы и пояснения
Markdown должны соответствовать текущему XMCD; готовые сцены CLI можно брать
за основу, но после изменения расчёта их значения тоже нужно обновить.

Зубчатое зацепление и кулачковый механизм рассчитываются самостоятельно:
сайт/CLI их не рассчитывают. Для кулачков есть пример ниже. Готового генератора
зубчатого зацепления здесь нет: построй отдельный расчёт по заданной методике
на библиотеке `xmcd`, укажи исходные данные и проверь геометрию и ограничения.
Не выдавай соседний пример за решение зубчатой передачи.

## Перед началом

Выбери ближайший генератор и прочитай только нужные материалы:

| Задача | Генератор |
|---|---|
| Общие сведения о кулачке и ролике | `scripts/intro.py` |
| Метрический синтез рычажных механизмов | `scripts/metric_synthesis.py` |
| Четырёхтактный двухцилиндровый ДВС | `scripts/engine.py` |
| Строгальный станок и установившийся цикл | `scripts/shaper.py` |

| Синтез кулачковых механизмов | `scripts/cams.py` |

Для обозначений и API смотри [`references/STYLE.md`](references/STYLE.md), для алгоритмов и границ примеров — [`references/METHODS.md`](references/METHODS.md). При изменении эталонного примера или разборе расхождения прочитай [`references/CORRECTIONS.md`](references/CORRECTIONS.md). Не загружай все семь генераторов в контекст без необходимости.

Фотографии в `assets/scans/` — визуальный эталон того, как в итоге должны выглядеть расчётные листы: композиция, подписи, схемы, таблицы и графики. Они нужны для понимания оформления и сверки переноса, а не для OCR или автоматической подстановки чисел. Номер JPG на единицу больше печатного номера страницы.

Абсолютный эталон — фотографии в `assets/scans/`, а не каталог `scripts/`. Генераторы — примеры утилизации библиотеки и связанные учебные фрагменты, а не гарантированно правильные решения и не универсальный шаблон курсового проекта. В них есть комментарии для агента-читателя и захардкоженные контрольные величины, которые в настоящем проекте должны быть вычислены на предыдущих листах Mathcad. Комментарии для агента в итоговый лист не переносить; контрольные числа из примера не выдавать за вычисленные результаты и заменять полным расчётом. Для нового варианта заново проверь топологию, сборку, исходные данные, режим движения, законы сил и границы расчёта. Восстановленные параметры помечай в листе как выбранные или восстановленные.

## Запуск

Требуется Python 3.11+ и `lxml` из [`requirements.txt`](requirements.txt). Запускай команды из этой папки; Mathcad для генерации не нужен:

```bash
python -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
.venv/bin/python scripts/engine.py --out /absolute/path/to/project/engine
.venv/bin/python scripts/build_all.py --out /absolute/path/to/project/examples
```

Каждый генератор создаёт классический `.xmcd`, отчёт статической проверки и постраничную запись переноса в указанном каталоге. Всегда передавай `--out` с путём в рабочий проект пользователя: без него
генератор пишет в `output/` внутри навыка. Не добавляй результаты генерации в сам навык. `vendor/xmcd/src/xmcd` — встроенная библиотека; её исходники не изменяй.

## Рабочий порядок

1. Зафиксируй нумерацию звеньев и точек, систему координат, направление вращения, заданные размеры, массы, моменты инерции, нагрузки, режим и требуемые результаты.
2. Запиши замкнутые векторные контуры и выбранную сборку. Сначала проверь положения, затем получи аналоги скоростей и ускорений дифференцированием по обобщённой координате. Для движущихся направляющих учитывай переносные и кориолисовы члены.
3. Выбери правильную постановку динамики: установившийся цикл, ОДУ с характеристикой двигателя или интеграл работы для неустановившегося движения. Не подменяй один режим другим.
4. Получи действительные скорости и ускорения, силы и моменты инерции, реакции групп, уравновешивающую силу или момент, таблицы и графики. Проверяй замыкание, невязки, баланс энергии и размерности.
5. Выполни статическую проверку генератора. Если целевой Mathcad доступен, открой лист, пересчитай его нативно и визуально проверь матрицы, графики и разбиение; до этого результат имеет статус «сгенерирован, нативно не проверен».

## Желательная нативная проверка

После генерации попробуй найти установленный Mathcad 15 или Mathcad 14. Открой полученные `.xmcd`, выполни полный пересчёт и вручную проверь ошибки, `Given/Find`, интегралы, матрицы, графики и раскладку. Для управления используй Computer Use, COM API или другой доступный аналог. Если Mathcad или интерфейс управления недоступен, явно сообщи, что выполнена только статическая проверка; не выдавай её за нативный пересчёт.

## Неизменяемые соглашения

- Результат — XML3.0.3 `.xmcd`, не Mathcad Prime `.mcdx`; переименование расширения не является конвертацией.
- Числа в примерах заданы в СИ, углы внутри функций — в радианах, вывод углов — через `/deg`, `ORIGIN=0`.
- `φ` и `s` — разные обобщённые координаты. Не дифференцируй по времени величину, которая в примере является аналогом по `φ` или `s`.
- Действительное ускорение имеет оба слагаемых: `q''·u² + q'·a`.
- Сохраняй семейства имён `X_A`, `Y_S2`, `φ_2`, `ω_q2`, `ε_q2`, `V_qS2X`, `a_qS2X`, `M_прC`, `I_прII`, `A_Σ`, `Φ_2X`, `M_Φ2`, `R_21X`. Литеральный подстрочный индекс (`R_21X`) и индекс массива (`R_21X[i]`) не смешивай.
- Печатные числа помечай как контроль «Скан» и не подставляй вместо вычислений. Ошибочный исходный контроль не является целью подгонки.

Для углов реакции помни: в листах Mathcad `atan2(x,y)` получает сначала компоненту X; NumPy использует порядок `(y,x)`. Скачки на разрезе угла сравнивай по модулю `2π`, не сглаживай физические разрывы нагрузки.

Для графиков с координатой, заданной через `π`, `2π`, `4π` и другие кратные `π` величины, явно задавай границы оси X (`x_bounds`). Например, для `φ/deg` полного оборота используй `(0, 360)`, для двух оборотов — `(0, 720)`. Иначе Mathcad может округлить автоматический диапазон до `0…400` или `0…800` и оставить пустое место. Параметр `width` задаёт только физическую ширину области графика и эту проблему не исправляет.

Для поиска положений и экстремумов используй ограниченный действительный вызов `root(f(x), x, a, b)`. Переменная `x` должна быть локальным параметром функции, а `a` и `b` — проверенным участком одной ветви с противоположными знаками на концах. Двухаргументный `root` с начальным приближением может выйти из действительной кинематической ветви даже при существующем действительном корне; широкий интервал, содержащий несколько нулей, даёт ошибку о знаках конечных точек. После генерации проверь в Mathcad, что оба корня и их значения `/deg` вычисляются без красных сообщений.

## Python → Mathcad

`scripts/book.py` строит XML и намеренно не вычисляет Python-выражения. `D('X_A(φ)', 'l_OA*cos(φ)')` создаёт определение Mathcad; `Given/Find`, производные, интегралы, программы и графики остаются редактируемыми. Минимальный внешний генератор может импортировать адаптер так:

```python
from pathlib import Path
import sys

SKILL = Path('/path/to/mathcad-mechanisms')
sys.path.insert(0, str(SKILL / 'scripts'))
from book import Book, cli

def build():
    b = Book('variant', 'Исследование механизма. Вариант …')
    b.text('Исходные данные', heading=True)
    b.D('l_OA', 0.2, why='Выбранное значение нового варианта.')
    b.D('φ_0', 0)
    b.D('ω_q1', 1)
    b.D('φ_1(φ)', 'φ_0+ω_q1*φ')
    b.D('X_A(φ)', 'l_OA*cos(φ_1(φ))')
    b.derivative('V_qAX', 'X_A')
    return b

if __name__ == '__main__':
    cli(build)
```

Параметр `x_bounds` в `Book.plot()` фиксирует диапазон математической оси; не подменяй его шириной региона. Библиотека не внедряет непроверенный бинарный picture-компонент; геометрию, заданную координатами, строй редактируемым графиком.
